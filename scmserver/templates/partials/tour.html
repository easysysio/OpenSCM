1 — Register a system

Install the agent on a machine. It enrols itself, reports its inventory, and stays connected. 

curl -fsSL https://repo.openscm.io/install.sh | sh -s -- \
    --server {% if tour.server_url %}{{ tour.server_url }}{% else %}https://your-openscm-server{% endif %} \
    --token  <enrolment-token>

{% if tour.has_token %} Replace <enrolment-token> with one of your enrolment tokens. Tokens are shown only once, when they are created — if you no longer have it, issue a new one. {% else %} You do not have an enrolment token yet. Create one first; the token value is shown only once, at creation. {% endif %} {% if not tour.server_url %}
Set your public URL under Settings so this command is filled in for you. {% endif %}

2 — Write a test

A test is one check: a file permission, a running service, a sysctl value, the output of a command. Each test has elements and conditions that decide PASS, FAIL or N/A.

The quickest start is the Policy Store, which carries ready-made CIS-style content you can install and run as-is.

Browse the Policy Store Create a test
{% endif %} {% if 4 in tour.screens %} {# ── Screen 4 — build a policy ───────────────────────────────────── #}

3 — Build a policy

A policy is a set of tests applied to a set of systems or groups. The policy is what gets scored, scheduled and reported on.

Go to Policies
{% endif %} {% if 5 in tour.screens %} {# ── Screen 5 — run it ───────────────────────────────────────────── #}

4 — Run it and watch

Run the policy now, or put it on a schedule. Results land in the compliance report and build a trend over time.

You can reopen this any time from Quick start in the user menu.
