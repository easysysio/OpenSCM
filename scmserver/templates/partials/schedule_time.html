{# Shared by policies_add.html and policies_edit.html. Schedule times are stored and compared in UTC. A datetime-local input works in the viewer's own time and sends no zone, and the server used to store what it received as if it were UTC — so every schedule ran early or late by the viewer's UTC offset, and the edit page showed the stored UTC time as if it were local. This script: (1) shows a stored UTC time (data-utc) in local time, (2) on submit, fills _tz_offset with the offset for the CHOSEN moment so the server can convert it (schedule::local_to_utc), and (3) for Custom (Cron) hides the picker — the expression decides the next run — and explains that cron is evaluated in UTC. Without JavaScript the picker stays empty on the edit page, which the server reads as "keep the current time". #}
